# 图片元素自动分层与文字可编辑项目开发文档

## 1. 项目名称

**图片元素自动分层与文字可编辑重建系统**

可选产品名称：

- Image Layer Decomposer
- PSD Layer Rebuilder
- 图片智能拆层工具
- 海报 PSD 智能还原工具
- 图片转可编辑设计稿工具

---

## 2. 项目背景

在实际设计、运营、电商、海报制作、二次编辑等场景中，经常会遇到只有一张 JPG、PNG、截图或压平后的图片，但没有原始 PSD、AI、Figma、Canva 工程文件的情况。

用户希望能够将一张普通图片重新拆解为多个可编辑图层，例如：

- 背景层
- 产品图层
- 人物图层
- 装饰元素图层
- 图标图层
- 普通文字图层
- 特效文字图层
- 色块、按钮、边框、阴影等设计元素

尤其是文字部分，用户希望识别后能够重新生成为可编辑文本，而不是继续保留为图片像素。

传统方式需要设计师手工抠图、重排文字、重建图层，耗时较长。因此本项目希望通过 OCR、图像分割、图像修复、图层重建等技术，构建一个自动或半自动的图片拆层与可编辑重建工具。

---

## 3. 项目目标

### 3.1 总体目标

用户上传一张图片后，系统自动识别图片中的主要视觉元素和文字内容，将其拆分为多个图层，并尽可能重建为可编辑格式。

最终输出可以包括：

- 可编辑在线画布
- SVG 文件
- HTML/CSS 文件
- 分层 PNG 资源包
- PSD 文件
- JSON 工程文件
- PNG 预览图

### 3.2 核心目标

1. 自动识别图片中的文字内容。
2. 自动识别文字位置、颜色、字号、行距、对齐方式等基础样式。
3. 将普通文字重建为可编辑文本对象。
4. 自动抠出图片中的主要视觉元素。
5. 自动修复被移除文字后的背景区域。
6. 将不同元素重新组织为图层结构。
7. 支持用户手动修正识别错误、合并图层、拆分图层、修改文本。
8. 支持导出为可再次编辑的设计文件或兼容文件。

### 3.3 非目标

第一阶段不追求以下能力：

1. 100% 还原原始 PSD 的完整图层结构。
2. 100% 识别原始字体名称。
3. 100% 还原复杂文字特效，例如金属字、3D 字、强发光、液态字、复杂渐变字。
4. 100% 还原 Photoshop 的所有混合模式。
5. 100% 自动判断所有图层真实前后关系。

本项目更现实的目标是：

> 自动完成 60% 到 80% 的拆层和文字重建工作，剩余部分交给用户在编辑器中手动微调。

---

## 4. 用户场景

### 4.1 电商封面二次编辑

用户只有一张闲鱼、电商、淘宝、拼多多、宣传图等压平图片，希望修改其中的价格、标题、卖点、按钮、联系方式等文字。

系统处理后：

- 背景保留为图片层。
- 商品主体抠出为独立图层。
- 原文字区域被清除并修复背景。
- 识别出的文字被重新生成为可编辑文本框。
- 用户可以直接修改文字内容。

### 4.2 海报模板复用

用户看到一张优秀海报，希望将其拆成可编辑模板，方便替换产品、标题、日期、网址等内容。

系统处理后：

- 海报背景成为底层。
- 装饰元素、图标、LOGO 尽量拆成独立 PNG 层。
- 普通标题、说明文字、网址重建为文本层。
- 用户可以导出 SVG、PNG 或 PSD。

### 4.3 PSD 文件丢失后的恢复

设计师只剩下压平后的 PNG 或 JPG，希望尽量恢复成可编辑文件。

系统处理后：

- 生成近似 PSD。
- 普通文字尽量可编辑。
- 复杂效果保留为图像层。
- 支持继续在 Photoshop 中二次编辑。

### 4.4 批量图片改字

用户有大量相似版式的图片，例如几十张营销图，只需要批量替换其中的日期、价格、活动文案。

系统处理后：

- 自动识别固定位置文字。
- 提供批量替换规则。
- 自动导出新图。

## 6. 核心功能模块

## 6.1 图片上传模块

### 功能说明

负责接收用户上传的图片文件，并进行基础校验和预处理。

### 支持格式

- PNG
- JPG / JPEG
- WebP
- BMP
- TIFF，可作为后续扩展

### 处理内容

1. 校验文件大小。
2. 校验图片尺寸。
3. 转换颜色空间。
4. 修正 EXIF 方向。
5. 生成原图备份。
6. 生成低分辨率预览图。
7. 生成任务 ID。

### 建议限制

MVP 阶段建议限制：

- 单张图片最大 20MB。
- 最大分辨率 6000 × 6000。
- 超大图自动缩放用于分析，最终导出时再映射回原图尺寸。

---

## 6.2 图像预处理模块

### 功能说明

提升后续 OCR、分割、轮廓检测的稳定性。

### 主要步骤

1. 图像去噪。
2. 对比度增强。
3. 边缘增强。
4. 色彩空间转换。
5. 缩放到模型适合的尺寸。
6. 保留原图与处理图之间的坐标映射关系。

### 技术点

- OpenCV 图像处理
- Pillow 图像读取和转换
- RGB / RGBA / HSV / LAB 色彩空间处理

---

## 6.3 OCR 文字检测与识别模块

### 功能说明

识别图片中的文字区域、文字内容、文字方向、文字行和段落结构。

### 输入

- 原始图片
- 预处理图片

### 输出

每一个文本块的数据结构：

```json
{
  "id": "text_001",
  "type": "text",
  "content": "示例文字",
  "bbox": [100, 200, 300, 260],
  "polygon": [[100, 200], [300, 200], [300, 260], [100, 260]],
  "confidence": 0.95,
  "language": "zh-cn",
  "direction": "horizontal",
  "font_size_estimated": 42,
  "color_estimated": "#ffffff",
  "background_color_estimated": "#000000",
  "editable": true
}
```

### 技术选型

优先推荐：

- PaddleOCR

备选：

- Tesseract OCR
- EasyOCR
- 云 OCR API，可作为商业增强版

### 中文识别建议

中文海报、电商图、宣传图优先使用 PaddleOCR。原因是中文场景中的艺术字、紧凑排版、多行文字、竖排文字较常见，普通 OCR 容易识别不稳定。

### 识别后的处理

1. 合并同一行文字。
2. 合并同一段落文字。
3. 判断标题、正文、按钮文字、角标文字。
4. 估算字体大小。
5. 估算文字颜色。
6. 判断是否可能为艺术字。
7. 判断是否适合重建为可编辑文本。

---

## 6.4 文字样式估算模块

### 功能说明

将 OCR 得到的文字像素尽量重建为文本样式。

### 需要估算的属性

- 字体大小
- 字体颜色
- 字重
- 行高
- 字间距
- 水平对齐方式
- 垂直对齐方式
- 旋转角度
- 是否有描边
- 是否有阴影
- 是否有渐变
- 是否有发光

### 估算方法

#### 字号估算

根据文字框高度进行估算：

```text
font_size ≈ bbox_height × 修正系数
```

中文一般可取：

```text
font_size ≈ bbox_height × 0.85 到 1.05
```

不同字体会有差异，后续可以让用户在编辑器中微调。

#### 颜色估算

从文字区域中采样高对比度像素，排除背景色后取主色。

可用方法：

- K-Means 聚类
- 颜色直方图
- 前景/背景分离
- 采样 OCR mask 区域

#### 字重估算

可根据笔画宽度、黑白连通区域、边缘密度估算：

- 笔画细 → Regular
- 笔画粗 → Bold
- 笔画极粗 → Heavy / Black

#### 字体识别

字体识别很难，MVP 阶段不建议作为强依赖。

建议策略：

1. 使用系统默认字体作为替代。
2. 中文默认使用思源黑体、阿里巴巴普惠体、微软雅黑等常见字体。
3. 英文默认使用 Arial、Helvetica、Inter 等字体。
4. 提供字体下拉框让用户手动更换。
5. 后续可增加字体匹配模型。

## 6.5 文字区域移除与背景修复模块

### 功能说明

为了让文字可以重新编辑，需要先从原图中去掉原有的像素文字，再在上面放置可编辑文本层。

### 输入

- 原图
- OCR 文字 mask

### 输出

- 去除文字后的背景图
- 修复后的背景图层

### 技术方案

#### 方案 A：OpenCV Inpaint

适合小面积、简单背景。

优点：

- 速度快
- 部署简单
- 不依赖大模型

缺点：

- 复杂背景修复效果差
- 大面积文字区域容易出现糊痕

#### 方案 B：LaMa 图像修复

适合复杂背景和大面积文字去除。

优点：

- 修复效果更自然
- 适合海报背景

缺点：

- 需要模型推理
- 服务端成本更高

#### 方案 C：扩散模型 Inpainting

适合高级版本。

优点：

- 修复能力强
- 视觉效果好

缺点：

- 速度慢
- 结果不可控
- 可能改变原图风格

### MVP 建议

MVP 阶段：

- 默认使用 OpenCV Inpaint。
- 对复杂场景提供“高级修复”选项。
- 高级修复可使用 LaMa 或其他深度学习修复模型。

## 6.6 元素分割模块

### 功能说明

识别并分割图片中的非文字元素，例如产品、人物、图标、装饰图形、色块、按钮等。

### 分割类型

1. 主体分割
2. 背景分割
3. 装饰元素分割
4. 色块分割
5. 图标分割
6. 规则图形分割
7. 边框和线条分割

### 技术方案

#### SAM / SAM2

用于通用物体分割。

适合：

- 产品
- 人物
- 动物
- 较明显的独立元素
- 用户手动点选后自动生成 mask

#### OpenCV 轮廓检测

适合：

- 色块
- 按钮
- 规则图形
- 矩形边框
- 线条
- 简单图标

#### 背景去除模型

适合：

- 人像抠图
- 商品抠图
- 单主体图片

可选：

- rembg
- U²-Net
- MODNet

### 自动分割难点

完全自动判断一张复杂海报中“哪些东西应该成为独立图层”非常难。

例如：

- 背景纹理是否要单独拆出来？
- 光效是否算独立元素？
- 阴影应该属于主体还是单独一层？
- 多个重叠元素如何判断前后关系？

因此产品上建议采用：

> 自动初拆 + 用户手动修正

## 6.8 图层排序模块

### 功能说明

尝试推断各元素之间的前后层级。

### 基础排序规则

1. 背景层放最底部。
2. 大面积色块通常位于背景上方。
3. 主体物体通常位于中间层。
4. 文字通常位于较上方。
5. LOGO、标签、按钮文字通常位于最上方。
6. 阴影通常位于对应主体下方。

### 排序依据

- 元素面积
- 元素透明度
- 是否文字
- 是否位于边缘
- 是否覆盖其他对象
- 是否有明显投影
- OCR 层优先置顶

### 注意事项

图层排序无法保证完全准确，必须允许用户在编辑器中调整前后顺序。

## 6.9 在线编辑器模块

### 功能说明

提供用户可视化编辑拆层结果的界面。

### 基础能力

1. 显示画布。
2. 显示图层列表。
3. 选中图层。
4. 移动、缩放、旋转图层。
5. 编辑文字内容。
6. 修改字体、字号、颜色。
7. 显示/隐藏图层。
8. 锁定/解锁图层。
9. 删除图层。
10. 重命名图层。
11. 调整图层顺序。
12. 导出文件。

### 高级能力

1. 手动框选元素并生成新图层。
2. 使用画笔编辑 mask。
3. 合并图层。
4. 拆分图层。
5. 重新 OCR 某个区域。
6. 重新修复某个区域背景。
7. 一键替换所有相同文字。
8. 批量导出。

### 前端技术选型

推荐：

- React
- TypeScript
- Konva.js 或 Fabric.js
- Zustand / Redux
- Tailwind CSS
- Web Worker

### Konva.js 与 Fabric.js 对比

#### Konva.js

优点：

- 性能较好
- 适合复杂画布交互
- React 生态较友好
- 图层、拖拽、缩放、变形比较方便

#### Fabric.js

优点：

- 设计编辑器场景成熟
- 文本对象、图形对象支持较丰富
- JSON 序列化方便

建议：

- 如果以设计编辑器为主，可以优先 Fabric.js。
- 如果以复杂画布性能和自定义交互为主，可以优先 Konva.js。

## 6.10 导出模块

### 6.10.1 导出 PNG

将当前画布渲染为普通图片。

用途：

- 直接发布
- 电商封面
- 海报预览

### 6.10.2 导出透明 PNG 图层包

将每个图层导出为独立透明 PNG，并附带 JSON 描述文件。

输出结构：

```text
export.zip
├── project.json
├── preview.png
├── layers
│   ├── background.png
│   ├── object_001.png
│   ├── object_002.png
│   └── text_placeholder.png
```

### 6.10.3 导出 SVG

将文字层、形状层转为 SVG 对象，将复杂图片元素作为嵌入图片。

优点：

- 文字可编辑
- 矢量形状可编辑
- 兼容浏览器
- 适合轻量编辑

限制：

- Photoshop 对 SVG 的编辑能力有限
- 复杂阴影和混合模式不一定完全一致

### 6.10.4 导出 HTML/CSS

将设计稿转为绝对定位的 HTML 页面。

适合：

- Web 预览
- 批量改字
- 生成自动化海报
- 通过浏览器截图导出 PNG

### 6.10.5 导出 PSD

目标：让 Photoshop 可以打开，并尽量保留分层。

PSD 导出建议分阶段实现：

#### 第一阶段

- 背景图层
- 图片图层
- 文字以图片形式导出

#### 第二阶段

- 普通文字尝试生成为 Photoshop 可编辑文本层
- 保留基础字体、字号、颜色、位置

#### 第三阶段

- 支持简单形状层
- 支持阴影、描边等部分效果

注意：

PSD 格式复杂，开源库对“写入完整可编辑 PSD 文本层”的支持通常有限。不要把 PSD 作为第一阶段唯一核心输出，建议优先保证 JSON、SVG、HTML 和 PNG 图层包稳定。

## 9. 核心算法流程

## 9.1 完整处理流程

```text
用户上传图片
    ↓
生成任务 ID
    ↓
图片预处理
    ↓
OCR 文字检测
    ↓
文本区域 mask 生成
    ↓
文字样式估算
    ↓
原图文字移除
    ↓
背景修复
    ↓
非文字元素分割
    ↓
规则图形检测
    ↓
图层生成
    ↓
图层排序
    ↓
生成项目 JSON
    ↓
返回编辑器
```

---

## 9.2 OCR 与文字重建流程

```text
输入图片
    ↓
PaddleOCR 检测文字区域
    ↓
识别文字内容
    ↓
合并文字行和段落
    ↓
分析颜色、字号、字重
    ↓
生成文本图层
    ↓
生成文字 mask
    ↓
从背景中移除原文字
```

### 判断文字是否适合编辑

适合可编辑文本：

- 普通黑体、宋体、圆体等字体
- 无复杂特效
- 横排或简单竖排
- 颜色单一
- 背景对比明显

不适合可编辑文本：

- 3D 字
- 金属字
- 强渐变字
- 扭曲变形字
- 手写艺术字
- LOGO 字
- 和背景强融合的文字

不适合时的处理方式：

- 保留为图片图层
- 标记为“疑似艺术字”
- 允许用户手动改为文本层

---

## 9.3 元素分割流程

```text
输入去文字后的图片
    ↓
使用 SAM 生成候选 mask
    ↓
过滤过小区域
    ↓
过滤文字区域
    ↓
合并相似区域
    ↓
生成元素 PNG
    ↓
估算元素边界框
    ↓
生成图片图层
```

### mask 过滤规则

- 面积小于总图 0.05% 的忽略
- 面积大于总图 90% 的通常视为背景
- 与文字 mask 大面积重叠的忽略或归类为文字
- 过度碎片化的区域合并
- 透明边缘需要 feather 处理

---

## 9.4 色块和形状检测流程

```text
输入图片
    ↓
颜色聚类
    ↓
边缘检测
    ↓
轮廓提取
    ↓
矩形/圆角矩形/圆形判断
    ↓
生成 shape 图层
```

适合检测：

- 按钮
- 标签
- 价格牌
- 纯色色块
- 边框
- 分割线
- 圆形装饰

## 15. 关键难点与解决方案

## 15.1 难点：文字不是原始文本，而是像素

### 问题

图片中的文字已经被栅格化，无法直接编辑。

### 解决方案

- 使用 OCR 识别文字内容。
- 使用坐标框生成新文本层。
- 原文字区域用图像修复去掉。
- 样式只能近似还原。

---

## 15.2 难点：字体无法准确识别

### 问题

OCR 通常不会返回字体名称。

### 解决方案

- MVP 使用默认字体。
- 根据语言和风格选择推荐字体。
- 提供用户手动选择。
- 后续开发字体匹配模型。

---

## 15.3 难点：复杂艺术字难以编辑

### 问题

艺术字可能有渐变、描边、3D、发光、扭曲等效果。

### 解决方案

- 判断复杂文字是否适合编辑。
- 普通文字转文本层。
- 复杂艺术字保留为图片层。
- 用户可手动替换为文本。

---

## 15.4 难点：自动拆层边界不准确

### 问题

AI 分割出来的元素边缘可能不精确。

### 解决方案

- 使用 mask 平滑和 feather。
- 提供手动修边工具。
- 支持重新分割。
- 支持用户框选区域生成图层。

---

## 15.5 难点：PSD 导出复杂

### 问题

PSD 是复杂格式，尤其是可编辑文本层和图层样式。

### 解决方案

- 第一阶段不把 PSD 作为唯一核心输出。
- 优先保证 JSON / SVG / HTML / PNG 图层包。
- PSD 先做基础分层图片版本。
- 后续逐步增强可编辑文本层支持。

- 简单纯色背景去文字后基本无明显痕迹。
- 渐变背景去文字后视觉可接受。
- 复杂背景允许有瑕疵，但用户可以手动修正。

## 22.3 编辑器验收

- 用户可以修改文字内容。
- 用户可以移动、缩放文本层。
- 用户可以修改颜色、字号。
- 用户可以导出 PNG。

## 22.4 导出验收

- PNG 导出与编辑器预览一致。
- SVG 导出可以在浏览器打开。
- ZIP 图层包包含 project.json 和资源文件。

## 23. 风险评估

| 风险 | 等级 | 说明 | 应对方式 |
|---|---|---|---|
| OCR 识别错误 | 高 | 复杂字体、低清晰度图片易错 | 提供手动编辑和重新识别 |
| 字体还原不准 | 高 | 很难识别原始字体 | 使用近似字体 + 手动选择 |
| 背景修复不自然 | 中高 | 复杂背景去字效果差 | 增加高级修复模型 |
| 自动分层不准确 | 高 | 复杂海报元素关系难判断 | 自动初拆 + 手动修正 |
| PSD 导出不完整 | 高 | PSD 格式复杂 | 分阶段实现，不作为 MVP 核心 |
| 推理成本高 | 中 | SAM/LaMa 需要较多算力 | MVP 先用轻量方案 |
| 大图处理慢 | 中 | 高分辨率图片耗时长 | 限制尺寸，异步任务，GPU Worker |

## 25. 最小可行产品定义

MVP 最终交付形态：

> 用户上传一张图片，系统自动识别普通文字，将文字变成可编辑文本层，并生成去除原文字后的背景图。用户可以在网页编辑器中修改文字、调整样式，最后导出新的 PNG 图片和 SVG/JSON 工程文件。

MVP 不承诺：

- 完美 PSD。
- 完美字体识别。
- 完美元素拆层。
- 完美复杂艺术字编辑。

但 MVP 必须做到：

- 普通文字可改。
- 画面大体一致。
- 用户能手动调整。
- 导出结果可用。

## 26. 结论

本项目技术上可行，但不能简单理解为“把一张图片一键变回原始 PSD”。更准确的定位应该是：

> 通过 OCR、图像修复、图像分割和在线编辑器，将压平图片尽可能重建为可编辑设计稿。

建议开发策略：

1. 第一阶段先做“文字可编辑”。
2. 第二阶段做“背景修复和图层包”。
3. 第三阶段做“SAM 分割和手动拆层”。
4. 第四阶段做“PSD 导出增强”。

这样可以最快做出可用产品，避免一开始陷入 PSD 格式、字体识别、复杂特效还原等高难度问题。
